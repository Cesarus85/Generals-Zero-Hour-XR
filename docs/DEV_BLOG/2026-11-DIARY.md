# Development Diary - November 2026

## 2026-11-01: Generals: Zero Hour XR runs on Steam Frame

First run on a real Steam Frame through Lepton ("Lepton Development",
`adb connect frame:5555`, data push over USB with `adb forward tcp:5556
tcp:5555`). Lepton is LineageOS 18.1 / Android 11 (API 30), Mesa (Freedreno
GLES 3.1, Turnip Vulkan). The OpenXR runtime is SteamVR (`vrclient.so`),
registered as the system runtime in
`/vendor/etc/openxr/1/active_runtime.json`; the app's static Khronos loader
finds it unchanged.

SteamVR reports 49 extensions, including `XR_KHR_opengl_es_enable` (the GLES
renderer works unchanged), `XR_KHR_android_create_instance`,
`XR_FB_display_refresh_rate`, `XR_FB_foveation*`,
`XR_VALVE_frame_controller_interaction` and `XR_EXT_hand_tracking`. It does not
offer `XR_FB_passthrough`, `XR_META_virtual_keyboard` or the FB scene
extensions; these were already optional. The runtime rejects OpenXR 1.1, and
the 1.0 fallback from the probe commit works. The recommended view is
1728x1728. Both hands bind `/interaction_profiles/oculus/touch_controller`,
so input works unchanged. The single ray from the pointing hand is the same
design as on Quest.

Changes in this step:
- Manifest: `org.khronos.openxr.intent.category.IMMERSIVE_HMD` next to the
  Oculus VR category. No change on Quest.
- Passthrough on Frame: SteamVR offers `XR_ENVIRONMENT_BLEND_MODE_ALPHA_BLEND`.
  Eye buffers already clear to alpha 0 outside game content (the Quest
  passthrough-layer contract), so frames now end with ALPHA_BLEND when
  `XR_FB_passthrough` is missing and the runtime supports it. Ground View
  stays OPAQUE. Quest keeps OPAQUE plus its FB passthrough layer.

Owner acceptance on the Frame: the room is visible behind the menu; the
tabletop appears in the room; selection and orders work. Engine boot takes
about 2 s. The match runs at about 70-72 fps on High (1920x1920 per eye,
multiview), against about 46 fps at Balanced on Quest 3. Debug APK
`1.2.36-frame-probe.3`; the same APK serves Quest and Frame.

Open for the Frame: a text-entry fallback without the Meta keyboard (Direct
Connect IP, names, chat), the in-app game-data import flow under Lepton,
refresh rate and foveation, LAN and voice against Quest, and release
packaging and notes.

## 2026-11-01: Steam Frame alpha 1 (1.2.37-frame-alpha.1)

The owner asked for a very early Frame alpha so testing can start the next
day. It ships as a GitHub pre-release; Quest 1.2.36 stays "Latest", because
the Frame changes have not been re-tested on Quest.

A first-run test on the Frame (app data cleared, the external
`.generalszh_gamepath.txt` recovery hint moved aside) showed:
- The XR activity correctly hands off to the game-data assistant, and the
  assistant and folder picker render as Lepton windows.
- Lepton runs 2D activities in maximized freeform windows. Android 11
  withholds system bar insets from floating windows, but Lepton's navigation
  bar (`[0,1017][1920,1080]`) still overlays the display. As a result, the
  picker's bottom actions (Cancel / Use This Folder) never received taps.
  `InsetUtil` now rebuilds the missing bottom inset from window and display
  bounds. This applies only to multi-window activities on a device that shows
  a navigation bar, and only when the framework reported no bottom inset.

The loading-presenter test now extracts the real `xrFrameBlendMode` helper and
checks it: ALPHA_BLEND only without FB passthrough and outside Ground View.
The test also gains the keyboard spy it had lacked since the Meta keyboard
commit (96e0553); without it, the test no longer compiled.
