# Development Diary - September 2026

## 2026-09-25: Ground View horizon no longer depends on head yaw

Owner report: in Ground View, distant hills appeared at the edge of vision and
vanished when looked at directly. Cause: the observer used a flat depth far
plane at `kXrObserverFarMetres` (60 m). A point at distance d and angle a from
the view axis has depth d*cos(a), so terrain between 60 m and the square
terrain coverage was clipped straight ahead but visible off axis.

Fix, observer-only: the fragment stage discards beyond a horizontal 60 m circle
around the head (the shader board is head-relative; `uXrAspect` carries the
negative radius). The projection and render-camera far planes move to
`kXrObserverClipFarMetres` (1.5x), so they never clip inside that circle, even
for the highest terrain. The tabletop branch (`uXrAspect>0`) and its clipping
are unchanged. The shader validates as GLSL ES 3.0. Checks pass: 71 ground
observer (new horizon checks included), 788 workspace and 449 shadow scope; the
NDK stereo tests compile.

Device regression in the first test APK (`1.2.35-ground-horizon-test`): Ground
View could not be entered. `beginXRStereo` accepted only `-1` as a negative
aspect, so the new `-60` radius made every observer stereo begin fail. The
empty capture then triggered P17 recovery ("late capture loss"), which cancels
the observer. The host tests had not covered that validation. It is now the shared
`gxXrStereoAspectValid()` in `XRStereoShader.h`, used by the pipeline and
checked by the ground observer test (75 checks). Rebuilt as
`1.2.35-ground-horizon-test.2`; not yet checked in the headset.
